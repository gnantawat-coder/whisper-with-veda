# Veda 0.1.25 — ประเมินจำลองผู้ใช้ 5 คน (2026-09-10)

**นี่คือ cognitive walkthrough โดยผู้ช่วยผ่านบุคลิกสมมติ ไม่ใช่การทดลองกับคนจริง** ตัวเลขที่อ้างเป็นตัวเลขจริงจากเครื่องผู้ใช้ (latency.csv, diagnostics, VALIDATION.md) แต่พฤติกรรม "ผู้ใช้" เป็นการจำลอง ห้ามนำไปอ้างเป็นผลวิจัย

ข้อมูลจริงที่ใช้ประกอบ: q5_0 ในแอป มัธยฐาน 1.85 s (1.39–2.93 s, n=6), ข้อความพัก 1/6 ครั้ง · CER เสียงผู้ใช้ 10.7% (7.1% ไม่นับรูปแบบตัวเลข) · คำอังกฤษในประโยคไทยยังผิดทุกครั้ง · ต้องขอสิทธิ์ใหม่ 3 รายการทุกการอัปเดต (ad-hoc) · Snap Translate ครั้งที่สองเคยค้าง (แก้ใน 0.1.25 ยังรอยืนยัน)

## ข้อสรุป: เพิ่ม / ตัด / คงไว้

### เพิ่ม (เรียงตามคุ้มค่า)
1. **Snap เลือกหลวม ๆ ได้** — แคปทั้งจอครั้งเดียว (มีสิทธิ์แล้ว) ให้ผู้ใช้ลากบน overlay ของ Veda เอง → ขยายกรอบตามกล่องข้อความจาก OCR ให้ครบบรรทัด, คลิกเดียว = ย่อหน้าใต้เมาส์, มีแว่นขยายตอนลาก · ตอบคำถาม "ขยายข้อความให้ Snap ง่ายขึ้นไหม" ได้ตรงกว่า: **อย่าขยายข้อความ ให้ระบบอภัยการลากไม่พอดีแทน** เพราะปัญหาไม่ใช่ตัวเล็ก แต่คือขอบกรอบ
2. **แนะนำคู่คำอนุมัติอัตโนมัติ** จากส่วนต่าง "คุณพูด" vs "โมเดลได้" ในตัวอย่าง กดอนุมัติคลิกเดียว — ทำให้ฟีเจอร์ที่มีอยู่ถูกใช้จริง
3. **สถานะ "กำลังถอดเสียง… 1.8 วิ"** บนแถบระหว่างรอ — ต้นทุนต่ำสุด ลดความรู้สึกช้าที่วัดได้ 1.4–2.9 วิ
4. **หน้าตั้งค่าครั้งแรก 3 ขั้น** (ไมค์ → Accessibility → Screen Recording) พร้อมเหตุผลและตรวจสถานะ — แก้ปัญหาที่ผู้ใช้ทุกคนเจอทุกอัปเดต
5. เปลี่ยนคำ "ข้อความพัก" → "ยังไม่ได้พิมพ์" · ปักหมุดการ์ด Snap

### ตัด / ซ่อน
- ปุ่ม "จัดช่องว่างอัตโนมัติ" → เปิดตลอด ไม่ต้องเป็นตัวเลือก
- ปุ่มสลับทิศทางบนการ์ด → ย้ายเข้าเมนู ⋯ (ระบบเลือกถูกตั้งแต่แรกในทุกกรณีที่ทดสอบ)
- ศัพท์เทคนิคในหน้าตรวจระบบ → หลัง disclosure ทั้งหมด

### คงไว้ (อย่าแตะ)
- ทุกอย่างบนเครื่อง ไม่มี log ข้อความ · ข้อความพักไม่หายข้ามอัปเดต · ปุ่มลัดตั้งเองได้ · การ์ดแปลปิดเองเมื่อคลิกที่อื่น

### ยังแก้ไม่ได้ด้วยดีไซน์
- ขอสิทธิ์ใหม่ทุกอัปเดต — ต้อง signing identity (ผู้ใช้เลือกเลื่อนไว้)
- คำอังกฤษในประโยคไทย — ข้อจำกัดโมเดล ลดได้ด้วยคำอนุมัติเท่านั้น
